# ARES integration: a contract-first recommendation

Candidate case study for the Energy Systems and AI Research Lead role, NEST
programme, Open Earth Foundation.

Prepared 29 August 2026. The commit history of this repository spans the work.

## The argument in one line

The interface is the boundary, and tight coupling is necessary exactly to the
extent that the boundary is underspecified.

## What is here

Built:

| Path | What it is |
|---|---|
| `docs/decisions.md` | What was chosen, and what it was chosen over |
| `docs/partners.md` | Each partner read off the brief, every line marked stated, inferred or unknown |
| `docs/assumptions.md` | Assumptions that materially shape the recommendation |
| `docs/options.md` | Working notes: the option space, kept so the choices can be checked |

Scaffolded, not yet built. Each is a stub with its intended contents in its
docstring, so what is missing is legible rather than implied:

| Path | What it will be |
|---|---|
| `src/` | The artifact: the contract model, the four readers, the checker, the page |
| `data/` | Four partner interface declarations, synthetic, in four formats |
| `deck/` | The board deck, eight slides |
